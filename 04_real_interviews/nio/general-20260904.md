    80|## 题解：层序建树 + BFS 逐层扩展
    81|### 题目问题拆解
    82|给一个层序序列，把二叉树还原出来，再求根到最远叶子的路径上有多少个节点。
    83|这是一道难点全在输入解析的树遍历题：求深度只要一趟遍历，真正会翻车的是层序串怎么对应父子关系，以及  到  时链状树会把递归压爆栈。
    84|### 算法实现
    85|层序序列的约定是：从根开始逐层写下每个位置，`#` 占位空节点，而只有非空节点才往下发两个元素当它的左右孩子。
    86|于是后面每个节点的位置都会因空节点整体前移，解析必须用队列，套不了完全二叉树的下标公式  与 。序列 `{1,#,2,3}` 里节点  排在第  位，它的左孩子  紧挨在第  位，而下标公式要去第  位找，早已越界。
    87|算法实现上分两步：
    88|第一步，建树。根编号  入队，读取指针指向第  个元素。每弹出一个节点就连取两个元素当它的左右孩子：是 `#` 就把这一侧记成 ，否则新建节点并入队等着领自己的孩子。末尾被省略的空节点表现为元素提前耗尽，循环条件带上指针越界即可。
    89|第二步，求深度。仍用队列，但整层整层地弹：先让  加一，再固定住此刻的队列长度 ，把这  个节点全弹完并把非空孩子入队，一轮正好走完一层。
    90|这里必须迭代而不能递归：输入若是一条左链，递归深度就等于 ，Python 默认上限  会抛 RecursionError，C++ 与 Java 同样爆栈。空树 `{}` 一个元素都不剩，直接输出 。
    91|### 时空复杂度分析
    92|**时间复杂度** ：。建树时每个元素只被扫一次，求深度时每个节点只进出队列一次。瓶颈在读入本身，序列长度与节点数同阶， 已是下界。
    93|**空间复杂度** ：。左右孩子表各  项，队列最多同时装下最宽的一层，仍是 。
    94|**Python**
    95|
    96|```
    97|# 二叉树最大深度 - 层序建树 + BFS 逐层扩展
    98|from collections import deque
    99|
   100|
   101|def build_tree(s):
   102|    """把层序序列还原成左右孩子表，返回 (左孩子表, 右孩子表, 节点总数)。"""
   103|    body = s.strip()
   104|    # 去掉包裹整个序列的一对花括号，剩下的才是逗号分隔的元素
   105|    if body.startswith("{"):
   106|        body = body[1:-1]
   107|    # 空树写作 {}，去掉花括号后什么都不剩
   108|    if not body:
   109|        return [], [], 0
   110|
   111|    tokens = body.split(",")
   112|    # left_son[u] / right_son[u] 存孩子编号，-1 表示这一侧是空的
   113|    # 根节点固定编号 0，之后节点的编号按它在层序里出场的先后依次递增
   114|    left_son = [-1]
   115|    right_son = [-1]
   116|    # 队列里放"已经建好、但还没领到孩子"的节点，层序序列正是按这个顺序把孩子发下来的
   117|    q = deque([0])
   118|    # 0 号 token 已经用作根节点，孩子从 1 号 token 开始往下发
   119|    i = 1
   120|    while q and i < len(tokens):
   121|        u = q.popleft()
   122|        # 只有非空节点才会消耗两个 token 当它的左右孩子，这是层序序列的关键约定
   123|        for side in range(2):
   124|            if i >= len(tokens):
   125|                break
   126|            token = tokens[i]
   127|            i += 1
   128|            # '#' 只是占位的空孩子，不产生新节点，也不会往下发孩子
   129|            if token == "#":
   130|                continue
   131|            # 新节点的编号就是当前已建节点数，正好与它的出场顺序一致
   132|            v = len(left_son)
   133|            left_son.append(-1)
   134|            right_son.append(-1)
   135|            if side == 0:
   136|                left_son[u] = v
   137|            else:
   138|                right_son[u] = v
   139|            q.append(v)
   140|    return left_son, right_son, len(left_son)
   141|
   142|
   143|def max_depth(left_son, right_son, n):
   144|    """从根出发按层扩展，一共走过多少层就是最大深度。"""
   145|    # 空树一层都没有，深度是 0
   146|    if n == 0:
   147|        return 0
   148|    depth = 0
   149|    # 从根出发，队列里始终装着"下一层要展开的节点"
   150|    q = deque([0])
   151|    # 用队列迭代而不是递归：链状树深度可达 10^5，递归必爆栈
   152|    while q:
   153|        depth += 1
   154|        # 先固定住当前层的节点数，把这些全弹完才算走完一层
   155|        for _ in range(len(q)):
   156|            u = q.popleft()
   157|            if left_son[u] != -1:
   158|                q.append(left_son[u])
   159|            if right_son[u] != -1:
   160|                q.append(right_son[u])
   161|    return depth
   162|
   163|
   164|# 整棵树压在一行里，可能有几十万字符，一次性读入整行
   165|s = input()
   166|# 先把序列还原成树，再在树上求深度，两步各管一件事
   167|lson, rson, total = build_tree(s)
   168|print(max_depth(lson, rson, total))
   169|```

   172|## 题目描述
   173|AK机有一个长度为  的整数数组  和一个整数 。她想让数组  里的元素进行配对，配对的两个数  需要满足  是偶数。
   174|数组  的每个元素最多配对一次。
   175|AK机想要尽可能多的配对，你能帮帮她吗？
   176|## 输入描述
   177|第一行两个整数 。
   178|第二行  个整数 。
   179|## 输出描述
   180|第一行先输出一个整数 ，表示最大的配对数。

   186|```

   200|**样例解释**
   201|是奇数。 是奇数、 是偶数，乘积  是偶数，所以  可以配对；同理  与  也都合法。这三对用掉了  共  个元素，只剩下  无法再配，因此最大配对数为 。
   202|## 题解：奇偶分类贪心
   203|### 题目问题拆解
   204|从数组里挑出尽量多的元素对，每个元素至多用一次，每一对  要满足  为偶数，并把方案打印出来。
   205|这是一道把条件翻译成奇偶性之后就地化简的贪心题：难点不在配对本身，而在看出合法性只取决于元素与  是否同奇偶，从而把  个数压成两类。
   206|### 算法实现
   207|先化简条件。乘积为偶等价于两个因子里至少有一个是偶数，而  为偶等价于  与  同奇偶：
   208|或
   209|同奇偶指两数同为奇数或同为偶数。于是把与  同奇偶的元素叫好数、记  个，其余叫坏数、记  个。一对合法当且仅当里面至少有一个好数；坏数配坏数时两个因子全是奇数，乘积必为奇数，永远不合法。
   210|再看最多能配几对。每一对至少吃掉一个好数，故对数不超过 ；每一对吃两个元素，故对数又不超过 。两条上界合起来：
   211|这个上界能取到，让好数先去带坏数即可：先配  对，剩下的好数彼此再两两成对。 时总数是 ； 时好数全部用来带坏数、得  对。两种情形都恰好顶到上界，贪心因此最优。
   212|落到实现上只需一趟扫描：按  把元素分进好数表与坏数表，前  个好数与同样多的坏数一一成对，好数表剩下的部分按相邻下标两两成对。输出的是元素值而不是下标，重复值也不影响，因为每个元素只被放进一张表一次。 时两轮循环一对都产生不了，输出  与空方案，正是答案。
   213|### 时空复杂度分析
   214|**时间复杂度** ：。分类扫一趟，两轮配对合计不超过  次。瓶颈在读入这  个数本身， 已是下界。
   215|**空间复杂度** ：。好数表与坏数表合起来正好装下全部  个元素，答案最多  对。
   216|**Python**
   217|
   218|```
   219|# 偶数配对 - 奇偶分类贪心
   220|
   221|
   222|def split_by_parity(a, k):
   223|    """把元素分成好数与坏数：好数满足 x+k 为偶数，即 x 与 k 同奇偶"""
   224|    good = []
   225|    bad = []
   226|    # (x+k) 的奇偶只由 x 与 k 的奇偶决定，取模判一次就能定类，不必真去做加法
   227|    for x in a:
   228|        if (x + k) % 2 == 0:
   229|            good.append(x)
   230|        else:
   231|            bad.append(x)
   232|    return good, bad
   233|
   234|
   235|def match_pairs(good, bad):
   236|    """(x+k)(y+k) 为偶等价于两数至少有一个是好数，据此贪心配对"""
   237|    pairs = []
   238|    # 每一对至少吃掉一个好数，故对数不超过好数个数，下面的构造正好顶到这个上界
   239|    # 坏数配坏数永远是奇数乘奇数，只能靠好数带，所以先一对一带走尽量多的坏数
   240|    t = min(len(good), len(bad))
   241|    for i in range(t):
   242|        pairs.append((good[i], bad[i]))
   243|    # 好数彼此就能配对，把带完坏数后剩下的好数两两一组，一个都不浪费
   244|    rest = good[t:]
   245|    # 剩余好数为奇数个时最后一个会落单，步长 2 的循环条件自然把它跳过
   246|    for i in range(0, len(rest) - 1, 2):
   247|        pairs.append((rest[i], rest[i + 1]))
   248|    return pairs
   249|
   250|
   251|# 读入数组长度、参数 k 与整个数组
   252|n, k = map(int, input().split())
   253|a = list(map(int, input().split()))
   254|
   255|# 先按奇偶分类，再在两张表上贪心配对，两步各管一件事
   256|good, bad = split_by_parity(a, k)
   257|pairs = match_pairs(good, bad)
   258|
   259|# 先输出对数，再逐行输出每一对的两个元素值（不是下标）
   260|print(len(pairs))
   261|for x, y in pairs:
   262|    print(x, y)
   263|```
