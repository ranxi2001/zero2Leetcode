# 计算机组成原理：程序怎样在硬件上运行

组成原理不是背 CPU 名词，而是回答：

```mermaid
flowchart LR
    A["一行高级语言"] --> B["机器指令"]
    B --> C["CPU 取指 译码 执行"]
    C --> D["寄存器 Cache 主存"]
    D --> E["控制器与 DMA"]
    E --> F["磁盘 网卡等设备"]
```

## 四个核心部件

| 部件 | 职责 |
|------|------|
| CPU | 执行指令、进行计算和控制 |
| 主存 | 保存当前运行程序和数据 |
| I/O 设备 | 与磁盘、网卡、键盘等外设交换数据 |
| 总线/互连 | 在部件之间传输地址、数据和控制信息 |

## 一条运行主线

执行 `total += values[index]` 时，至少涉及：

1. 程序计数器给出下一条指令地址。
2. CPU 取得并译码加载指令。
3. 地址生成单元计算 values[index] 的虚拟地址。
4. TLB/页表参与地址转换。
5. Cache 查找对应缓存行，未命中时访问更低层。
6. ALU 完成加法。
7. 结果写回寄存器或缓存。

高级语言的一行并不对应一次硬件动作。

## 面试中的典型连接

- 为什么数组通常比链表缓存友好？
- CPU 主频高为什么程序不一定更快？
- TLB miss 与 Cache miss 有什么关系？
- DMA 为什么能减少 CPU 搬运，但不能完全不需要 CPU？
- CAS 为什么能实现原子更新？
- 多核修改同一变量时，其他核心怎样看到新值？

这些问题会在操作系统的虚拟内存、锁和 I/O 中再次出现。

## 学习要求

每节都尝试回答：

- 数据当前在哪一层？
- 谁发起下一步动作？
- 状态保存在哪里？
- 发生 miss、冲突或异常后怎样恢复？
- 优化的是延迟、吞吐还是资源利用率？

## 零基础预备：这门课到底研究什么

**Computer Organization 直译**：计算机组成。

它不主要教某种编程语言，而是回答：

- 代码最终怎样变成机器指令。
- CPU 怎样执行指令。
- 整数、浮点和字符怎样表示。
- 数据为什么经过寄存器、Cache 和内存。
- 设备怎样把数据送进内存。
- 多个 CPU 核心怎样协调共享数据。

### 体系结构与组成原理

- **Architecture**：软件可见的约定，例如 ISA、寄存器和地址模型。
- **Organization**：硬件怎样实现约定，例如流水线、Cache 和控制器。

课程与面试中二者经常交叉。重点是知道“软件合同”与“硬件实现”属于不同层。

### 一行代码背后的硬件

```python
total = a + b
```

背后至少涉及：

1. 源文件字符编码。
2. 语言整数语义。
3. 编译器或解释器。
4. 目标 ISA。
5. 寄存器和 ALU。
6. 取指、译码和执行。
7. Cache 和主存。
8. 操作系统调度。

## 零基础硬件地图

### CPU

**Central Processing Unit，中央处理器。**

它持续执行机器指令，包含寄存器、执行单元、控制逻辑、流水线、Cache 和一个或多个核心。

### Register

**直译**：寄存器。

位于 CPU 内部，数量少、速度快，用于保存当前操作数、中间结果、程序计数器、栈指针和状态信息。

### Cache

**直译**：高速缓存。

保存近期可能使用的指令和数据，用较小容量换取更低的平均访问延迟。

### Memory

本课程通常用“内存”指 DRAM 主存：

- 容量比 Cache 大。
- 延迟比 Cache 高。
- 断电后数据丢失。
- 程序运行时的大部分数据最终映射到这里。

### Storage

SSD/HDD 等持久存储：

- 容量更大。
- 访问更慢。
- 断电后通常保留数据。
- 保存程序文件、数据库和文件系统。

### Controller

设备控制器连接 CPU/内存与具体设备，驱动通过寄存器、队列、中断和 DMA 使用它。

### Bus / Interconnect

负责在 CPU、内存和设备间传输地址、控制信息与数据。现代系统可能使用复杂互连网络，不一定是一根物理“总线”。

## 一条程序运行主线

```text
磁盘上的可执行文件
  -> 操作系统建立虚拟地址空间
  -> 所需代码页进入内存
  -> CPU 用 PC 取得下一条指令
  -> 指令先查 TLB 和 Cache
  -> 译码器识别操作
  -> 寄存器提供操作数
  -> ALU 或其他执行单元计算
  -> 结果写回寄存器或内存
  -> I/O 需要时通过控制器和 DMA
  -> 中断通知 CPU 处理完成
```

| 步骤 | 本课程章节 | 后续连接 |
|---|---|---|
| 文件变成指令 | 数据与指令 | OS 装载与进程 |
| PC 取指执行 | CPU 流水线 | OS 上下文切换 |
| 地址和数据缓存 | 存储层次 | OS 虚拟内存 |
| 设备传输 | I/O 与 DMA | OS 文件和网络 I/O |
| 多核共享数据 | 一致性与原子 | OS 锁与同步 |

## 初学者最容易混淆的概念

| 概念 A | 概念 B | 区别 |
|---|---|---|
| bit | byte | 二进制位 vs 通常 8 位组成的字节 |
| 地址 | 数据 | 地址用于定位，数据是被访问内容 |
| 硬盘 | 内存 | 持久大容量 vs 运行时主存 |
| 内存 | Cache | 大而慢 vs 小而快 |
| ISA | 微架构 | 软件合同 vs 具体硬件实现 |
| 延迟 | 吞吐 | 一个任务多久 vs 单位时间多少任务 |
| Cache miss | Page Fault | 数据缓存未命中 vs 页表无法完成访问 |
| 中断 | 异常 | 外部异步事件 vs 当前指令同步事件 |
| 原子性 | 缓存一致性 | 操作不可分割 vs 副本传播规则 |
| 并发 | 并行 | 一段时间推进 vs 同一时刻执行 |

## 每章怎样学习

### 第一遍：只建立图

每节先回答：

1. 参与者是谁。
2. 数据在哪里。
3. 谁向谁发请求。
4. 哪一步可能等待。
5. 最终状态改变了什么。

### 第二遍：加入数字

练习：

- 位数和范围。
- 地址 tag/index/offset。
- CPI/IPC。
- AMAT。
- Amdahl 加速比。
- 带宽与延迟。

### 第三遍：连接代码

观察：

- 一行源码的汇编。
- 顺序与随机内存访问。
- 编译优化前后。
- 多线程计数与 false sharing。

### 第四遍：练习表达

每个问题准备：

- 30 秒结论。
- 2 分钟机制。
- 一个工程例子。
- 一个边界或反例。

## 不需要死背什么

- 不必背完整 x86 或 Arm 指令表。
- 不必设计晶体管级 CPU。
- 不必背每款 CPU 的 Cache 参数。
- 不必背 PCIe 各代精确带宽。
- 不必背所有 MESI 消息。

必须理解：

- 固定位宽为什么溢出。
- 指令怎样经过 CPU。
- 为什么流水线会停顿。
- Cache 为什么有效、为什么失效。
- DMA 为什么减少 CPU 搬运。
- 缓存一致性为什么不等于线程安全。

## 学完本门后的验收

你应能从零解释：

1. 为什么二进制适合数字硬件。
2. 8 位补码为什么是 -128 到 127。
3. 为什么 `0.1 + 0.2` 可能不等于 `0.3`。
4. Unicode、UTF-8 与字节的关系。
5. 源码、目标文件和可执行程序的区别。
6. ISA、ABI 和微架构的区别。
7. PC、寄存器、ALU 和内存各做什么。
8. 流水线如何提高吞吐。
9. RAW、WAR、WAW 与控制冒险是什么。
10. 分支预测错误为什么浪费周期。
11. Cache line、局部性和三类 miss。
12. TLB miss 为什么不等于 Page Fault。
13. 轮询、中断和 DMA 如何配合。
14. MESI 解决什么、不解决什么。
15. false sharing 为什么修改不同变量也会慢。
16. 原子操作与内存顺序为什么必要。
